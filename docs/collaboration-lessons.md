# 通用协作复盘

这份复盘总结资料整理、任务委派、写作、图示和交付中的通用问题。**当前助手对理解偏差、过度干预和交付判断失当承担责任。** 改进重点是准确理解需求、明确分工，并把具体表达交给负责产出的执行者。

| 通用问题 | 改进做法 |
|---|---|
| 过早定调：将整理者的推测写成既定事实 | 分开记录用户要求、资料事实和分析建议，关键判断回查原始材料 |
| 过度设计：简单任务逐渐扩展为复杂流程和多个交付物 | 围绕当前目标选择必要步骤，沿用用户认可的内容与交付位置 |
| 过度约束：提前限定标题、段长、结构和素材顺序 | 交代目标、材料和必要要求，由产出负责人决定具体组织方式 |
| 职责混淆：资料整理和评审逐渐变成代写 | 整理者提供事实与出处，写作者组织表达，评审者提交建议，写作者执行修订 |
| 层次混杂：主体、组件、方法与结果挤在同一层 | 按对象职责和读者理解顺序组织内容，比较时采用相同的问题与条件 |
| 表达拥挤：抽象标题和长句承载过多概念 | 标题点明对象或问题，句子说清动作，段落随话题变化展开 |
| 图示模板化：多种关系被套入同一种图 | 根据图要解释的问题选择图型，先核对关系语义，再检查实际显示效果 |
| 验收偏移：字数、数量和程序通过被当成质量结论 | 按用户目标验收内容、理解成本与使用效果，分别说明工具检查覆盖的范围 |
| 过程信息侵入成品：核对记录和待办打断正文 | 成品直接呈现读者需要的内容，制作记录与待办另行保存 |
| 来源和版本混乱：指定执行者、实际产出与最终稿对应模糊 | 核对实际执行者及原始结果，明确当前采用稿、待核材料和附件的用途 |
| 个案固化为通用规则：项目事实和个人偏好进入公共指令 | 通用说明保存可复用经验，领域方法放入 references，项目事实放入本地知识资料 |

这些经验用于选择合适的做法。执行时根据当前任务采用相关项，具体规范随实际反馈修订。

问题已经出现时，助手按 [协作问题排查 Skill](../.agents/skills/collaboration-troubleshooting/SKILL.md) 定位原因、执行修复，并分别说明客观核验的结果和需要读者评价的效果。各类问题的处置方法如下：

- 过早定调、过度设计、过度约束和个案固化的处置方法见 [理解与范围](../.agents/skills/collaboration-troubleshooting/references/understanding-and-scope.md)。
- 职责混淆、来源和版本混乱的处置方法见 [角色与来源](../.agents/skills/collaboration-troubleshooting/references/roles-and-sources.md)。
- 层次混杂、表达拥挤、图示模板化和过程信息侵入成品的处置方法见 [表达与图示](../.agents/skills/collaboration-troubleshooting/references/expression-and-diagrams.md)。
- 验收偏移的处置方法和修复结果的报告方式见 [验收与结果说明](../.agents/skills/collaboration-troubleshooting/references/acceptance.md)。
