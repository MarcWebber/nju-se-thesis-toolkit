# 试用稿写作审阅

审阅对象：[飞书试用稿](https://bytedance.sg.larkoffice.com/docx/EiHVdCvlmoNTTsxjN3mloDMBgbh)。本次读取了既有五章全文，并回读飞书版本 27 的问题、设计和验证章节。

这份稿件更接近工具使用说明和交付记录。它能演示材料转换、编译和检查，却还没有充分展开工程论文所需的问题、设计选择和结果分析。自然表达也受此影响：正文不断介绍命令、列出文件、申明限制，读者很难跟住一个具体问题。更换写作模型值得尝试，同时需要重新组织交给它的事实材料。

## 具体问题

| 原文 | 阅读问题 | 修改方向 |
|---|---|---|
| “作者、学号和导师等正式信息尚未填写，不能作为学位论文提交。” | 制作状态打断了问题分析。 | 放入制作记录；正文解释材料转移在哪一步丢失了哪些信息。 |
| “转换命令读取完整飞书导出，连同文档 ID、版本和 reference_map 保存原始输入。” | 只列出保存对象，设计理由没有展开。 | 从缺图后的定位与修正讲起，再解释版本、原块位置和输入副本的作用。 |
| “15 个命令帮助加载成功”“37 个文件哈希一致” | 这是工具运行与文件交付检查，尚未回答转换是否完整、缺项能否找到。 | 正文围绕转换缺项、来源定位和页面显示组织实际案例；命令清单移到使用说明。 |

当前写作 Skill 已要求解释设计理由、使用实际依据和移出制作备注。这次主要是这些要求没有落实到稿件。继续增加禁词和固定段落模板，难以补上论证。

## 一段改写

以下由当前助手依据实际代码改写，用于确认写法；Gemini 尚未参与。对应原稿“总体设计—材料流向”的首段。

> 飞书正文与图片素材需要分别导出。转换器读取图片块时，要通过素材映射找到对应的本地文件。映射缺失时，它会在报告中记录该图片块的标识，并在生成的 TeX 中留下待处理标记。作者可以据此定位飞书中的对应图片，补齐本地素材及其映射，再重新转换。
>
> 为了判断问题发生在哪一版材料中，工具还保存本次使用的原始导出，并在报告中记录文档版本。这样，排查缺图时可以同时查看输入中的图片块、使用的素材映射和转换结果。正文修订仍在飞书完成，TeX 由修订后的源稿重新生成，避免两处正文分别修改后出现差异。

“保存输入与版本”对应 [documents.py](../thesis_cli/documents.py) 的 `import_document`；“缺少素材时记录块标识并生成标记”对应其中的 `material` 和 `issue`。最后一句是现有飞书源稿约定。本段没有推断处理速度、定位耗时或自动修复能力。

## 写作分工

[agent.yaml](../.agents/skills/nju-se-thesis/agents/agent.yaml) 定义材料分析、正文写作、事实审阅三个职责，由主 Skill 读取。正文写作优先使用用户指定的 Gemini Argon。reviewer 只返回原文位置、问题、依据和修改建议，正文与文件保持原样；writer 核对建议的依据，说明采纳情况并修改正文。上面的一段改写属于写作示例。

reviewer 当前由本助手承担，MiniMax M3 是待实测候选。[MiniMax 官方说明](https://www.minimax.io/blog/minimax-m3)已提供 M3 API 和长上下文能力，尚需用本稿实际检验问题发现、依据准确性与误报情况。候选名称不表示已经选用或调用。

本文件和 YAML 约束角色职责。外部 reviewer 接入时只发送本次材料，不配置文件或飞书写入工具；当前尚无独立执行器提供技术隔离。评审建议的采纳和正文修改由 writer 或作者负责。

当前已完成角色指令，模型调用尚未接通。`agent.yaml` 不是 Codex 原生的跨厂商调度配置；其中的模型偏好不会自动创建 Gemini 代理。本机尚未找到可用的 Gemini 命令、登录态或 API 配置，实际入口和模型 ID 待确认。

2026-10-10 核对的 [Google 公告](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/)仍说明 Argon 分阶段开放，[公开 API 模型目录](https://ai.google.dev/gemini-api/docs/models)未列出 Argon。官方 [Gemini CLI](https://geminicli.com/docs/cli/headless/)支持非交互调用，但安装 CLI 本身不能证明账号具有 Argon 权限。

接通后先用上面这一段的同一组事实调用实际模型，保留实际模型名称、输入与原始回答，再比较是否容易理解、因果关系是否充分、事实和术语是否准确。由作者判断是否采用该写法；不把程序检查、角色配置或主观评分当作写作质量验收。
