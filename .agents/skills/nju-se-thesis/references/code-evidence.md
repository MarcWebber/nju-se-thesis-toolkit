# 代码材料

先确认用户指定的仓库、版本和论文问题。用入口、调用方、数据结构、错误分支和测试定位证据，不生成另一套仓库索引或泛用分析框架。

| 论文任务 | 读取范围 | 交付内容 |
|---|---|---|
| 解释机制 | 入口、实现、调用方、异常分支 | 机制说明、源码位置、短代码段 |
| 画架构图 | 模块边界、生产装配、真实依赖 | 可编辑图源、SVG、论文用 PDF |
| 画时序图 | 同一次请求的调用链、异步与返回 | 参与者、调用顺序、失败分支 |
| 描述状态 | 状态定义、修改处、持久化与恢复 | 状态图、事件条件、终态 |
| 写验证章节 | 测试代码、运行结果、环境和数据 | 指标口径、复现方法、限制 |

将已读文件和结论对应起来，区分当前生产调用、测试替身和未接线代码。仅有源代码只能支持实现说明，不能证明上线、性能提升或创新性。

摘录命令独立运行，不要求初始化论文项目：

```bash
thesis excerpt /path/to/repo src/service.py /path/to/excerpt --start 20 --end 45 --revision COMMIT --caption 请求处理 --label lst:request
```

省略 `--revision` 时读取当前工作树并记录脏状态。交付包含原始摘录、内联 `lstlisting` 片段和来源清单。模板需加载 `listings`；中文代码还须检查 XeLaTeX 下的字体和换行。

按论文问题选最短的完整逻辑段，不为展示代码而贴整份文件。删节、改写和伪代码另存并说明，不能替换来源清单中的原始摘录。秘密、个人信息和内部地址需要作者确认脱敏后再用于对外交付。
