# 材料与提纲

配合 [共用规则](../SKILL.md#共用规则) 使用。

## 1. 输入

```text
论文主题与学校模板：
作者承担的工作：
材料位置与版本：
已有目录：
本次要整理的范围：
```

## 2. 步骤

1. 阅读材料，区分需求、设计方案、源码实现和运行结果。给重要判断保留文件、章节或代码位置。
2. 用一句话说明论文问题：什么场景下，哪个约束造成了什么困难。再对应作者的解决办法和验证材料。
3. 根据材料安排到二级标题。每节列出要回答的问题、可用依据和必要图表；没有材料支撑的部分列为建议，不预写结论。
4. 合并职责重复的小节。各章内容的分工见 [章节写作](writing-chapters.md#2-各章重点)，不要按功能菜单拆论文目录。
5. 输出论文主线、提纲和影响写作的材料缺口。题目尚未确定时，依据实际工作范围提出候选题目。

## 3. Example

以下为合成输入，用于演示提纲组织。

- 场景：设备按固定时段预约，同一设备同一时段只能有一条有效预约。
- 作者工作：冲突处理与通知模块。
- 已有材料：唯一约束、事务和通知调用代码，一次并发请求记录。
- 未提供：持续负载测量。

主线：说明系统如何限制重复预约，以及预约提交与通知发送的先后关系。

| 小节 | 要回答的问题 | 依据与图表 |
|---|---|---|
| 预约约束 | 什么请求构成冲突 | 需求说明、场景表 |
| 冲突处理 | 并发写入如何返回成功或冲突 | 唯一约束与事务代码、时序图 |
| 通知处理 | 何时发送，失败后发生什么 | 提交后的调用与异常分支 |
| 场景验证 | 这次并发请求产生了什么结果 | 请求记录、数据库记录 |

材料缺口：这次记录可用于描述给定场景的结果，不能据此安排已有性能提升结论。
