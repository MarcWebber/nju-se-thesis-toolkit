# 材料与提纲

配合 [共用规则](nju-se-engineering.md#共用规则) 使用。

## 1. 输入

```text
论文主题与学校模板：
作者承担的工作：
材料位置与版本：
已有目录：
本次要整理的范围：
```

## 2. 步骤

1. 阅读作者当前要求和原始资料，分别记录系统主体、业务能力、支撑组件、作者贡献与来源。名称和边界有歧义时回查资料，关键缺口向作者确认。
2. 材料整理者围绕实际场景说明已知问题、实现行为和运行结果，并将作者原话与自己的分析建议分别标明。
3. 写作者依据材料决定论文主线、题目和目录，标题层级与展开程度沿用作者本次要求。外部写作时，将原始材料与来源交给指定写作者，由其组织提纲。
4. 按[各章重点](writing-chapters.md#2-各章重点)区分背景、技术、需求、设计、实现与测试。标题直接使用实际对象或问题，各节围绕清楚的论证任务组织。
5. 交付本次要求的提纲与相关材料缺口，保留作者已认可的范围；待核判断单列为讨论项。

## 3. Example

以下为合成输入，用于演示提纲组织。

- 场景：设备按固定时段预约，同一设备同一时段只能有一条有效预约。
- 作者工作：冲突处理与通知模块。
- 已有材料：唯一约束、事务和通知调用代码，一次并发请求记录。
- 未提供：持续负载测量。

主线：说明系统如何限制重复预约，以及预约提交与通知发送的先后关系。

| 小节 | 要回答的问题 | 依据与图表 |
|---|---|---|
| 预约约束 | 什么请求构成冲突 | 需求说明、场景表 |
| 冲突处理 | 并发写入如何返回成功或冲突 | 唯一约束与事务代码、时序图 |
| 通知处理 | 何时发送，失败后发生什么 | 提交后的调用与异常分支 |
| 场景验证 | 这次并发请求产生了什么结果 | 请求记录、数据库记录 |

材料范围：这次记录支持给定并发场景的功能结果；持续负载与性能提升需要另有实测材料。
