# 章节写作

配合 [共用规则](nju-se-engineering.md#共用规则) 使用。

## 1. 输入

```text
操作：起草 / 续写 / 修改
目标章节与前后文：
本节问题：
事实材料与来源：
保留的术语、数字和引用键：
参考范文及希望借鉴的特点：
输出位置与形式：
```

## 2. 各章重点

沿用作者模板和本次范围，下表用于判断内容归属。标题、段落和具体展开由写作者结合材料组织。

| 内容 | 要写清什么 |
|---|---|
| 绪论 | 先讲清业务场景、实际问题、研究意义、相关工作与本文贡献；接口、字段和测试明细放入后文 |
| 相关技术 | 按实际技术或框架解释必要原理及采用理由；具体业务流程放入设计与实现章 |
| 需求分析 | 参与者、系统边界、正常与异常场景、可观察的验收条件 |
| 系统设计 | 目标约束、总体方案、关键取舍与代价；数据关系和接口语义 |
| 系统实现 | 关键机制的触发条件、处理对象、动作和结果 |
| 系统验证 | 验证问题、环境、方法、指标定义、实际结果及解释 |
| 总结 | 对论文问题的回应、完成的工作、实际限制与后续方向 |
| 摘要 | 主体已有的问题、工作与结果；中英文事实及结论范围一致 |

## 3. 起草与修改

1. 写作者确定本节要解释的关系，例如约束为何导致某项设计、一次操作如何改变数据、结果支持什么判断，并据此组织标题与段落。
2. 设计写选择依据，实现写实际行为。技术选型经历和比较结论采用对应决策材料；已有技术栈可直接说明其适用需求与工程作用。
3. 并发机制说明共享数据和原子操作边界；异步机制说明发送、提交、确认与重试的顺序。代码分析方法见 [代码与工程图表](writing-engineering.md)。
4. 验证段先报告观察，再解释原因。环境、负载、指标和计算口径应足以复核；区分功能场景结果与性能测量。
5. 参考范文用于理解论证推进、术语、引证和图文配合；章节细分、段落组织与技术选择围绕作者自己的材料展开。
6. 修改已有稿件时，先解决跳步、歧义、重复、事实冲突或证据错配，保留作者认可的章节与表达。事实核对意见由写作者判断并执行。

## 4. 表达

1. 用完整、肯定、直接的句子说清谁对什么做了什么，保留实际动作和影响结论的条件。
2. 相邻句子围绕同一意思承接，话题变化时换段。长句承载多个机制或结果时，按它们的关系拆开说明；段落长短随内容自然安排。
3. 标题直接指出实际对象或问题，使用作者确认的名称。技术原理、采用理由和应用关系按需要展开，小节组织由写作者决定。
4. 同一概念使用同一术语，关键结论少量加粗。多维比较用表，交互顺序和关系用适合语义的图。
5. 图后说明关键关系或结果如何支持正文，制作状态、资料核对过程与待补事项放在正文之外。
