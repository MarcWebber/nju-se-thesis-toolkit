# 全文修订

配合 [共用规则](nju-se-engineering.md#共用规则) 使用。reviewer 仅使用只审不改模式，交付评审建议；局部和全文修订由 writer 或作者执行。

## 1. 输入

```text
模式：只审不改 / 局部修订 / 全文修订
当前权威稿件：
本次范围：
支撑材料与导师意见：
必须保留的内容：
输出位置与形式：
```

## 2. 内容审阅

1. 对照作者当前要求与原始材料，先核对系统主体、业务能力、支撑组件和个人贡献，再检查标题、摘要与正文的对应关系。
2. 检查各章是否围绕同一问题展开。绪论先建立场景与工作主线，相关技术讲清必要背景，需求、设计、实现与测试承接具体工程内容。
3. 核对反复出现的术语、数字、单位、指标、研究阶段和系统边界。数值冲突先查数据来源与口径，不按出现次数决定正确值。
4. 阅读连贯段落，定位概念密集、反复跳转、长句堆叠和重复介绍的位置。意见说明具体阅读障碍，标题、措辞与组织由写作者调整。
5. 核对正文、结构图与源码的主体、关系和操作顺序；检查图型是否准确表达用例、调用、部署或状态语义，数据图回查原始数据。
6. 引用按 [引文核验](writing-literature.md#3-引文核验) 执行，相关工作围绕可比较的研究问题展开。文风意见参照实际原文；飞书评论由主助手或作者按要求调用 `$thesis-calibrate` 写入。`thesis compare` 结果用于定位字面重复，再结合引用与常用表述判断。
7. 发现事实问题时，指出相关图表、摘要和总结的位置与依据。评审建议集中于有材料支持的问题，保留作者认可的范围与写作者的组织权。

## 3. 交付检查

仅在用户要求论文文件交付时，由交付执行者完成；reviewer 仅读取已有检查结果和产物。

1. 核对作者模板和已取得的学院要求。学位类型、作者信息、字体和附录配置需检查实际内容。
2. 对当前源工程做静态检查与实际编译，检查日志，并查看最终 PDF 的公式、中文、代码换行、图表和裁剪。编译命令与检查边界见 [Skill 工具选择](../SKILL.md#工具选择)。
3. 图源、矢量导出和重绘检查按 [论文图表](diagrams.md) 执行。归档保留当前稿件、源工程、图源和必要数据，剔除凭据与未获准公开的材料。
4. 分别报告作者对内容与阅读体验的认可、实际读取范围、格式检查和页面视觉结果。字数、图表数量和命令运行结果作为进度信息列出。

## 4. 输出

按系统理解与论证、阅读体验、图文语义、格式的顺序列问题，给出位置、依据和修改方向。reviewer 只交建议；writer 判断采纳并完成正文修订。交付者沿用明确的权威稿件位置，区分可直接阅读的正文、待核稿件与原文件附件。

## 5. Example

以下为合成审阅案例。

输入：

- 摘要：所有场景下，P95 延迟降低 40%。
- 正文：并发数为 20 的一次测量，基线 P95 为 100 ms，方案为 70 ms。
- 图注：平均延迟对比。

| 位置 | 问题 | 依据与改法 |
|---|---|---|
| 摘要 | 百分比计算错误、范围扩大 | 差值除以基线为 30%；限定为给定的一次测量 |
| 图注 | 平均值与 P95 混用 | 回查绘图字段后使用实际指标名称 |

评审者将计算依据和适用范围交给写作者，由写作者决定摘要中的措辞与段落安排。
