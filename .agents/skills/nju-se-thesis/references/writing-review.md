# 全文修订

配合 [共用规则](../SKILL.md#共用规则) 使用。reviewer 仅使用只审不改模式，交付评审建议；局部和全文修订由 writer 或作者执行。

## 1. 输入

```text
模式：只审不改 / 局部修订 / 全文修订
当前权威稿件：
本次范围：
支撑材料与导师意见：
必须保留的内容：
输出位置与形式：
```

## 2. 内容审阅

1. 先读标题、摘要、目录和总结，找出论文声称解决的问题与取得的结果，再到相应正文和原始材料核对。
2. 检查需求、设计、实现和验证是否回应同一问题。功能数量不能代替工程贡献，基础框架和团队成果不能归为作者个人工作。
3. 核对反复出现的术语、数字、单位、指标、研究阶段和系统边界。数值冲突先查数据来源与口径，不按出现次数决定正确值。
4. 核对正文、结构图与源码的组件、关系和操作顺序；数据图回查绘图数据。只看图形不能判断数字正确。
5. 引用按 [引文核验](writing-literature.md#3-引文核验) 执行。按样文校准文风时，reviewer 返回评论建议；飞书评论由主助手或作者按用户要求调用 `$thesis-calibrate` 写入。重复句段用 `thesis compare` 比对指定资料，再核对引用与常用表述，不将相似度称为抄袭结论。
6. 发现事实问题时，指出引用它的图表、摘要和总结。导师要求补充验证时，缺少实际结果不能用结论性文字代替。

## 3. 交付检查

仅在用户要求论文文件交付时，由交付执行者完成；reviewer 仅读取已有检查结果和产物。

1. 核对作者模板和已取得的学院要求。学位类型、作者信息、字体和附录配置需检查实际内容。
2. 对当前源工程做静态检查与实际编译，检查日志，并查看最终 PDF 的公式、中文、代码换行、图表和裁剪。编译命令与检查边界见 [Skill 工具选择](../SKILL.md#工具选择)。
3. 图源、矢量导出和重绘检查按 [论文图表](diagrams.md) 执行。归档保留当前稿件、源工程、图源和必要数据，剔除凭据与未获准公开的材料。
4. 报告本次实际读取和检查的范围。局部审阅、样例编译和自动检查均不能代表整篇论文已经验收。

## 4. 输出

按事实与论证、跨章一致性、表达与格式的顺序列问题，给出位置、依据和具体改法。reviewer 只交建议；writer 执行修订任务时交付改后内容。

## 5. Example

以下为合成审阅案例。

输入：

- 摘要：所有场景下，P95 延迟降低 40%。
- 正文：并发数为 20 的一次测量，基线 P95 为 100 ms，方案为 70 ms。
- 图注：平均延迟对比。

| 位置 | 问题 | 依据与改法 |
|---|---|---|
| 摘要 | 百分比计算错误、范围扩大 | 差值除以基线为 30%；限定为给定的一次测量 |
| 图注 | 平均值与 P95 混用 | 回查绘图字段后使用实际指标名称 |

摘要相关句可改为：在并发数为 20 的该次测量中，方案的 P95 延迟为 70 ms，比基线的 100 ms 降低 30%。
