# 代码与工程图表

配合 [共用规则](nju-se-engineering.md#共用规则) 使用。

## 1. 输入

```text
论文问题：
仓库、版本与重点模块：
设计材料或运行数据：
任务：机制说明 / 代码摘录 / 结构图 / 数据图
绘图工具、横纵布局与论文栏宽：
输出目录：
```

## 2. 分析与写作

1. 按 [代码材料](code-evidence.md) 阅读入口、调用方、实现与异常分支，并保存来源。分析范围由论文问题决定。
2. 解释机制时，把业务约束对应到实际操作。重点读事务、共享状态、异步调用和错误处理；对配置同时检查传入位置与使用位置。
3. 从代码提取适合正文的完整逻辑段，省略框架细节后的版本标为伪代码。摘录命令与来源记录方式以代码材料为准。
4. 形成图前说明与图后分析：前者告诉读者看哪种关系，后者解释关键机制或数据现象。已有正文与代码不符时，定位差异，不修改业务代码迎合稿件。

## 3. 绘图与排版

1. 读取 [论文图表](diagrams.md)，按图中要表达的关系选型。图型要求、绘图命令、重绘检查和矢量交付只在该文件维护。
2. 数据图先核对原始列、单位、缺失值和聚合口径。误差线需要重复测量或相应计算依据；保留数据清洗规则。
3. 飞书画板使用原生节点，并读取实际节点与预览。保存节点快照；未经重导入验证，不承诺快照可无损恢复。另按论文图表要求交付可编辑源、SVG 和矢量 PDF。
4. 表格比较同一组维度，区分未测、缺失和零。宽表先精简或拆分，确需横页时再横排；转换命令见工具集 README。
5. 交付机制说明、源码定位与实际生成的图件。分别说明源码阅读、运行观察、图源重建和视觉检查的完成范围。

## 4. Example

以下为合成调用过程：

```text
接收固定时段的设备预约请求
在事务中插入有效预约记录
唯一约束冲突则返回冲突结果
提交成功后调用外部通知服务
通知失败只记录日志
```

时序图应表达：

1. 客户端、预约服务、数据库、外部通知服务四个参与者。
2. 冲突路径直接返回；成功路径先提交，再调用通知。
3. 通知失败落到日志记录，不增加材料中没有的队列或重试。

图后说明：

预约记录提交后，服务才调用通知接口。通知发送失败不会撤销已提交的预约，当前实现仅记录失败日志。因此，预约结果与通知结果需要分别记录。

交付内容：原生画板、节点快照、可编辑图源、SVG、矢量 PDF、插图片段及重绘说明。
