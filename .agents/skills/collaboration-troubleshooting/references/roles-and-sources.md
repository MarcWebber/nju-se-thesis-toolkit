# 角色与来源

本篇处理两类问题：角色越过授权，执行者与版本对应混乱。助手依据会话中仍然有效的授权、用户的最新选择和已有的原始记录来修复。

## 确认授权

助手从当前会话中查找仍然有效的授权，例如用户指定的写作者、模型、入口和各角色的职责；用户最新的选择覆盖较早的安排。用户已经要求修复时，助手在这一授权范围内直接执行。任务已经获得授权、角色安排需要补充时，助手按项目惯例补齐这部分安排，把修复范围保持在已授权的任务之内，并在回复中说明沿用了哪项惯例。

## 判断出处

`git status` 和 `git diff` 显示哪些文件和行发生了变化；内容由谁写成，则需要原始记录来确认。助手判断出处时查阅原始记录：会话记录、子代理或外部模型的原始输出、提交记录中的作者与说明，以及用户的明确陈述。记录能够对应上时，助手按记录认定出处；记录只能提供部分线索时，助手把内容视为用户当前成果保留，并在回复中说明出处仍待确认。

## 职责混淆

**现象**：评审者直接改写了正文。整理者交出的「材料」已经是成稿，写作者只剩润色的余地。用户指定了写作者，成稿却由协调者写出或大幅改动。协调者落盘时顺手修改了写作者的文字。

**定位**：助手把每份产出与授权对照，依据原始记录确认实际作者，并判断这位作者是否有权写这一部分。

**修复**：

- 原始记录显示评审者直接改动了正文时，助手先查明用户是否采用或认可了这些改动。用户已经采用或认可的部分，按本节最后一条作为用户成果保留；其余改动由协调者恢复为写作者原稿，并整理成建议清单交给写作者。清单的每一条写明位置、问题、依据和建议方向，是否采纳由写作者或用户决定，修订也由他们实施。
- 整理者代写了成稿时，整理者把内容拆回事实、出处和要求，交给授权写作者重新组织；原稿作为参考材料附上，写作者自行决定是否参考。
- 协调者改动了成稿时，协调者按写作者的原始输出重新落盘，并把自己发现的问题作为建议回传写作者。
- 用户已经采用或继续编辑了越权内容时，助手把这些内容作为用户成果保留，在回复中说明它们的来历，由用户决定是否调整。

**确认方式**：落盘的正文与授权写作者的原始输出或用户的修订一致，每条评审建议都有写作者或用户给出的处理结论。

## 来源和版本混乱

**现象**：协作各方对哪份文件是最终稿说法各异。某份稿件被说成由指定模型撰写，运行记录却与这一说法存在出入。附件、正文和落盘文件的内容互相矛盾。

**定位**：助手根据会话记录、原始输出和文件历史填写下面的对应表。「当前用途」一栏只取四个值：采用稿、待核、附件或废弃。

| 文件或版本 | 实际执行者（模型、入口） | 生成时间 | 原始输出位置 | 当前用途 |
|---|---|---|---|---|

**修复**：助手依据记录把执行情况归入以下三种状态，并如实告诉用户当前属于哪一种。

- **调用受阻**：指定执行者因额度、权限等原因返回空输出或报错。助手保留调用记录，把对应产出标为待生成，并说明用户需要处理的额度或权限事项；条件恢复后，助手按现有授权再次调用指定执行者。等待期间出现的临时稿标为待核。
- **来源待核**：现有记录只能提供部分线索。助手把相关稿件标为待核，继续查找原始输出，并向用户说明已确认和待确认的部分。
- **执行者发生变化**：记录显示成稿出自其他执行者。助手把该稿标为待核，并按现有授权请指定执行者重新产出；用户明确选择采用其他执行者的稿件时，助手按用户的最新选择更新对应表。

助手确定唯一的采用稿，并在回复或记录中写明它的路径。待核材料和附件与采用稿分开存放，废弃版本移出交付位置或明确标注为废弃。助手对外说明执行者时，只陈述记录能够证明的内容。

**确认方式**：用户凭对应表能找到当前采用稿、它的执行者和原始输出，对外声明的执行者与运行记录一致。
