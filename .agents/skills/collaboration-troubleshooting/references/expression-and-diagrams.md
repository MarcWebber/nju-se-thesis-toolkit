# 表达与图示

本篇处理成品中妨碍读者理解的问题：层次关系混乱、表达拥挤、图示与实际关系存在出入，以及过程信息干扰正文。判断依据是读者实际遇到的理解障碍和内容之间的语义关系；具体的组织方式由写作者根据内容选择。按照职责约定，评审者指出问题和依据，负责该成品的写作者或用户实施修订。

## 层次混杂

**现象**：读者读到某个结果时，需要反复回翻才能弄清它属于哪个模块或哪种方法。几个方案放在一起比较时，各方案回答的问题或所处的条件各异，读者需要自行换算才能逐项对照。

**定位**：助手从读者的角度通读全文，标出需要回翻或让人产生疑问的位置，再检查这些位置上的内容关系：某项内容是另一项的组成部分、实现手段、前提还是结果，以及当前的排列方式是否表达出了这种关系。对于比较部分，助手检查各对象是否回答了同一组问题、是否处在同一组条件下。

**修复**：写作者按内容之间的实际关系调整组织，让读者读到某项内容时已经了解它的前提。先交代主体，再介绍组件、方法和结果，是一种常用的参考顺序；多种类型的内容放在同一层也可以成立，前提是读者能看懂它们之间的关系。比较内容需要对照时，写作者先确定比较的维度和条件，再从表格、并列小节和连续叙述中选择最清楚的一种。

**确认方式**：客观上，原先标出的回翻和疑问位置都补上了前提说明，比较对象使用了一致的维度和条件。主观上，结构是否顺畅由读者阅读后判断。

## 表达拥挤

**现象**：读者要读完正文才能知道这一节讲什么，例如「能力建设」「体系优化」这类标题。某些句子同时引入多个新概念，读者需要反复阅读才能复述它的意思。用户希望文字更容易读懂。

**定位**：助手找出读者卡住的具体标题、句子或段落，并分析原因：标题停留在抽象概括，句子的主语、动作或对象模糊，新概念出现得突然，或者段落中途换了话题。

**修复**：写作者针对具体原因修改。标题停留在抽象概括时，写作者把对象或问题写进标题，例如把「流程优化」改为「预约冲突的检测时机」。句子承载的内容过多时，写作者补足句子成分、调整语序或拆分句子；内容紧密相关、读者能够顺畅读懂的长句可以保留。新概念出现得突然时，写作者在它首次出现的地方给出简短说明。话题发生转换时，写作者另起一段或补充过渡。原有的事实、专业术语和引用全部保留。

**确认方式**：客观上，原有事实、术语和引用完整保留，标出的卡点都已修改。主观上，读者能否顺畅读懂由读者判断，助手在回复中说明改动的位置。

## 图示模板化

**现象**：时序、结构、数据流和状态变化被画成同一种方框连线图。同一张图中的箭头有时表示调用，有时表示包含，有时表示数据流向，读者需要猜测它的含义。渲染后的图出现文字重叠、裁切、乱码或比例失调。

**定位**：助手先用一句话写出这张图要回答的问题，再列出图中的元素和每条关系，并标注关系的语义，例如调用、包含、依赖、数据流向、时间先后或状态转换。随后，助手打开实际的渲染结果检查显示效果。

**修复**：写作者按图要回答的问题选择图型。下表列出常见的对应关系，具体选择以内容为准。

| 图要回答的问题 | 常用图型 |
|---|---|
| 谁在什么时候与谁交互？ | 时序图 |
| 系统由哪些部分组成，彼此如何依赖？ | 结构图或组件图 |
| 数据从哪里来，经过哪些处理，流向哪里？ | 数据流图 |
| 对象有哪些状态，状态之间怎样转换？ | 状态图 |
| 执行过程包含哪些步骤和分支？ | 流程图 |
| 数值的大小和变化趋势如何？ | 统计图 |

一张图中出现多种关系时，写作者用图例区分线型；读者仍需费力分辨时，写作者把它拆成多张图。写作者逐条核对图中的关系与事实材料是否一致，然后在实际使用的环境中渲染，修正重叠、裁切和字体问题。

**确认方式**：客观上，每条边都能用一句话读出含义并与材料一致，渲染结果显示完整、清晰。主观上，图示是否直观由读者判断。

## 过程信息侵入成品

**现象**：面向最终读者的正文中出现了制作过程的痕迹，例如待办标记、核对记录，或「根据评审意见修改」之类的修订说明，读者需要跳过这些内容才能读到正文。

**定位**：助手先确认这份文档的用途和读者。同样的内容在各类文档中作用各异：讲解 TODO 工具的教程需要展示 TODO 标记，验证记录需要保留核对过程，来源说明需要写明撰写模型。助手可以用现有的检索工具查找待办标记和修订说明，再逐条判断它们是否服务于这份文档的读者。

**修复**：对于仅服务于制作过程的信息，负责该成品的角色把它移到记录文件、待办清单或回复中，待补齐的材料缺口单独列给用户。服务于文档用途的内容原样保留。移出内容之后，负责该成品的角色检查上下文是否仍然衔接。

**确认方式**：客观上，移出的条目在新位置完整保存，服务于文档用途的内容完整保留。主观上，正文读起来是否连贯由读者判断。
