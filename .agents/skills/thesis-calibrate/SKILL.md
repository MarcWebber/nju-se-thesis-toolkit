# 文风校准

## 调用

```text
$thesis-calibrate 待审飞书链接
参照：PDF、样文链接或本地参考索引
范围：系统实现章
输出：原文评论与标记，暂不改正文
```

直接读取参考原文，使用已有 `lark-cli` 写评论。飞书操作按当前环境的文档、评论接口说明执行，鉴权复用现有登录。

## 执行

1. 读取待审章节和上下文，保留文档版本及 block ID。参照用户指定的文件；未另指定时检查当前工作目录的 `references/local/index.md`，再读取相关原页。只看索引不能算读过原文。
2. 从参考的具体段落判断对象和动作如何交代、论证如何推进、图表如何支撑正文。每条借鉴附 PDF 页码或样文位置，同时避开参考自身的缺陷。他人论文只校准文体；用户自己的样文才用于个人文风校准。
3. 对照待审稿指出重复、空泛评价、指代或因果问题。保留数字、术语、引用和必要限定，用当前项目材料提出改法，不能从参考移入事实、复述段落或借用独有图示。
4. 一条评论写清一个问题、依据和建议。事实未确认时提出核实项。用户只要预览时交建议；要求写回时继续下一节，不编辑 TeX。

## 飞书写回

1. 用 `docs +fetch --detail full` 复读目标块，用 `drive +list-comments --need-relation` 读取未解决评论，按 `has_more` 翻页。相同位置已有同类意见时不重复添加；原句已变时重新判断。
2. 按实际 block ID 创建局部评论。局部评论自带关联原文的评论标记，不额外把正文替换成彩色文字，也不删除或重建块。评论中引用确切问题短句，便于从段落级标记找到问题。

   ```bash
   lark-cli drive +add-comment --doc '飞书文档URL' --block-id '实际块ID' \
     --content '[{"type":"text","text":"问题：……\n依据：样文位置与具体差异。\n建议：……"}]' --as user
   ```

3. 回读评论，核对 comment ID、评论内容和 relation 中的 blockID，再回读原段落确认正文未变。只验证到块级时，明确称为段落标记，不声称逐字高亮。接口失败不自动改成全文评论；写入结果不确定时先读取，不盲目重发。
4. 交付文档直达链接、已写入条数、未完成项。权限错误停止写回并请求缺少的授权，不生成虚拟 comment ID 或宣称评论已落地。

文风判断是编辑意见，不是 AI 生成概率。重复内容另用 `thesis compare` 对指定资料比对；匹配结果仍须检查引号、引文和常见技术表述。
